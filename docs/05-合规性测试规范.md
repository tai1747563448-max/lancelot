# 05 · 合规性测试规范

> 状态：草案 v1.0
> 读者：合规性测试作者、Lancelot 维护者、adapter 作者（测试自己写的实现）
> 范围：定义如何验证一个实现"确实满足"端口契约——V1 仅覆盖 MemoryPort 与 ToolPort

---

## 这是什么

合规性测试（compliance test）是把 [`03-端口契约.md`](03-端口契约.md) 定义的 Protocol 从"纸面契约"变成"代码强制"的机制。

它解决一个具体问题：用户写了 `adapters/memory/sqlite/` 然后声明 `provides = ["MemoryPort"]`——Lancelot 凭什么相信这个 adapter **真的**满足 MemoryPort？答案是"它跑过了合规测试套件"。

## V1 范围

| 端口 | V1 有合规测试吗 | 原因 |
|---|---|---|
| `MemoryPort` | ✅ | adapter 必须满足 |
| `ToolPort` | ✅ | adapter 必须满足 |
| `ModelPort` | ❌ | Lancelot 内部实现（保留端口），不开放给 adapter |
| `ChannelPort` | ❌ | Lancelot 内部实现（保留端口），不开放给 adapter |

> **保留端口不写测试**：V1 的 `ModelPort` 和 `ChannelPort` 由 Lancelot 自身实现。如果它们坏了，应该跑 Lancelot 自身的单元测试（`tests/unit/`），而不是合规测试。合规测试的存在意义是约束**外部**实现。

## 这不是什么

- **不是 adapter 自己的单元测试**：adapter 可以（也应该）有自己的单元测试。但合规测试是**通用**的——任何声明 `provides = ["MemoryPort"]` 的实现都要跑同一套测试。
- **不是性能测试**：V1 不验证性能。
- **不是集成测试**：合规测试只测**单个 port 实现**的行为，不测多 port 协同。

## 测试分层

每个 port 的合规测试分三层：

### 第一层：静态签名检查

用 `inspect` 验证实现类的方法签名与 Protocol 描述匹配。

```python
import inspect
from lancelot.ports.memory import MemoryPort

def test_memory_port_signatures(adapter_instance):
    proto_methods = {
        name: sig for name, sig in inspect.getmembers(MemoryPort, predicate=inspect.isfunction)
        if not name.startswith("_")
    }
    impl = type(adapter_instance)
    for name, expected_sig in proto_methods.items():
        assert hasattr(impl, name), f"missing method: {name}"
        actual_sig = inspect.signature(getattr(impl, name))
        # V1 简化：只检查方法名存在 + 参数个数匹配（不做参数名严格匹配）
        assert len(actual_sig.parameters) == len(expected_sig.parameters), \
            f"{name}: parameter count mismatch"
```

V1 简化：不做参数类型严格匹配（避免 typing 表达差异导致的假阳性）。这一层只保证"方法存在 + 参数个数对"。

### 第二层：行为检查

跑一组**通用场景**，验证返回值与异常符合端口契约。

示例（MemoryPort 的核心场景）：

```python
def test_memory_port_put_get_roundtrip(adapter_instance):
    """put 一条 → get 同 key → 内容相同。"""
    entry = MemoryEntry(key="k1", value="hello")
    adapter_instance.put(entry)
    got = adapter_instance.get("k1")
    assert got is not None
    assert got.value == "hello"


def test_memory_port_get_missing_returns_none(adapter_instance):
    """get 一个不存在的 key 必须返回 None（不抛异常）。"""
    assert adapter_instance.get("nonexistent") is None


def test_memory_port_clear(adapter_instance):
    """clear 后 get 所有 key 必须返回 None。"""
    adapter_instance.put(MemoryEntry(key="a", value="1"))
    adapter_instance.clear()
    assert adapter_instance.get("a") is None


def test_memory_port_list_respects_limit(adapter_instance):
    """list(limit=N) 返回 <= N 条。"""
    for i in range(5):
        adapter_instance.put(MemoryEntry(key=f"k{i}", value=str(i)))
    result = adapter_instance.list(limit=3)
    assert len(result) <= 3
```

### 第三层：边界与异常

验证实现处理**异常输入**的方式。

```python
def test_memory_port_put_duplicate_overwrites(adapter_instance):
    """put 同 key 时实现可以选择覆盖或拒绝——但不能崩。"""
    adapter_instance.put(MemoryEntry(key="k1", value="first"))
    # 不抛异常
    adapter_instance.put(MemoryEntry(key="k1", value="second"))
    # 至少有一个值能 get 回来
    assert adapter_instance.get("k1") is not None
```

V1 简化：**不规定** put 重复时的语义（覆盖 / 拒绝 / 追加）。这条留给 adapter 自己的语义决定。合规测试只保证"不崩"。

## 测试套件组织

### 文件命名与位置

```
tests/compliance/
├── conftest.py                              # 公共 fixture
├── test_memory_port_compliance.py           # MemoryPort 合规套件
└── test_tool_port_compliance.py             # ToolPort 合规套件
```

### Fixture 模式

合规测试需要**每个 adapter 一个 fixture 实例**。用 pytest 的 parametrize 实现：

```python
# tests/compliance/test_memory_port_compliance.py
import pytest
from lancelot.adapters.memory.inmemory import create_memory

@pytest.fixture(params=[
    pytest.param(("memory.inmemory", create_memory), id="memory.inmemory"),
    # V1 之后可以加：
    # pytest.param(("memory.sqlite", create_sqlite_memory), id="memory.sqlite"),
])
def memory_adapter(request):
    """返回一个 (id, instance) 元组，让测试既能跑行为又能引用 id。"""
    adapter_id, factory = request.param
    instance = factory()
    yield adapter_id, instance
    # teardown：可调用 instance.clear() 但 V1 不强制
```

每个 adapter 通过 `tests/compliance/conftest.py` 或单独的 fixture 文件注册一次。

### 命令行调用

```bash
pytest tests/compliance/ -v
```

V1 的 CI 流程（文档化但不实现）：

```yaml
# 未来的 .github/workflows/test.yml 草案
- run: pytest tests/compliance/
```

## MemoryPort 合规套件细节

V1 测试用例完整列表：

| ID | 场景 | 层 |
|---|---|---|
| TC-MEM-01 | put + get round-trip 一致 | 行为 |
| TC-MEM-02 | get 不存在的 key 返回 None | 行为 |
| TC-MEM-03 | list(limit=N) 返回 ≤ N 条 | 行为 |
| TC-MEM-04 | list 默认 limit=100 | 行为 |
| TC-MEM-05 | clear 后所有 get 返回 None | 行为 |
| TC-MEM-06 | put 重复 key 不崩 | 边界 |
| TC-MEM-07 | 方法签名存在（put/get/list/clear） | 静态 |
| TC-MEM-08 | `get` 返回 `MemoryEntry \| None`，不抛异常 | 类型 |

不测的（V1 简化）：

- 持久化（V1 无持久化 adapter）
- 并发（V1 不强制并发安全）
- 容量上限（V1 不规定 max_entries 必须被强制）

## ToolPort 合规套件细节

V1 测试用例完整列表：

| ID | 场景 | 层 |
|---|---|---|
| TC-TOOL-01 | `invoke(**kwargs)` 返回 `ToolResult` | 类型 |
| TC-TOOL-02 | `invoke` 返回的对象有 `content` 非空字符串 | 行为 |
| TC-TOOL-03 | `invoke` 返回的对象有 `tool_call_id` 字段（任意值即可） | 行为 |
| TC-TOOL-04 | `name` 是非空字符串 | 类型 |
| TC-TOOL-05 | `description` 是非空字符串 | 类型 |
| TC-TOOL-06 | `parameters_schema` 是 dict | 类型 |
| TC-TOOL-07 | `invoke` 抛 `ToolError`（非裸 `Exception`） | 异常 |
| TC-TOOL-08 | 方法签名存在（name / description / parameters_schema / invoke） | 静态 |

不测的（V1 简化）：

- 参数 schema 与 invoke 参数实际匹配（V1 不验证）
- LLM 视角的"参数合理性"
- 工具调用的副作用（如网络请求是否成功）

## 关于错误类型的特殊检查

合规测试**要求** adapter 抛 Lancelot 错误家族异常，而不是裸 `Exception`：

```python
def test_memory_port_raises_lancelot_errors(adapter_instance):
    """如果实现抛异常，必须是 MemoryError（继承自 LancelotError）。"""
    from lancelot.errors import LancelotError, MemoryError

    # 触发一个会让实现抛异常的边界场景
    # （V1 的 put/get 路径不应该抛，但实现可能在内部做非法操作）
    try:
        # 用例：拿到一个非法 entry
        with pytest.raises((MemoryError, LancelotError)):
            raise MemoryError("simulated")
    except MemoryError:
        pass  # OK
```

V1 不写"必须抛"的负面测试（因为大部分 adapter 实现可能根本不抛异常）；只写"如果抛了，类型必须对"的正向保证。

## 测试组织模板

每个 `test_<port>_compliance.py` 必须遵循这个结构：

```python
# tests/compliance/test_memory_port_compliance.py

"""MemoryPort compliance suite.

所有声明 provides = ["MemoryPort"] 的 adapter 必须通过本文件的所有测试。
"""
import pytest
from lancelot.domain import MemoryEntry
from lancelot.adapters.memory.inmemory import create_memory


@pytest.fixture(params=[
    pytest.param(("memory.inmemory", create_memory), id="memory.inmemory"),
])
def memory_adapter(request):
    adapter_id, factory = request.param
    instance = factory()
    yield adapter_id, instance
    # teardown 可选


# === 第一层：静态签名 ===

class TestSignature:
    def test_required_methods_exist(self, memory_adapter):
        ...

    def test_method_parameter_count(self, memory_adapter):
        ...


# === 第二层：行为 ===

class TestBehavior:
    def test_put_get_roundtrip(self, memory_adapter):
        ...

    def test_get_missing_returns_none(self, memory_adapter):
        ...


# === 第三层：边界 ===

class TestEdgeCases:
    def test_put_duplicate_does_not_crash(self, memory_adapter):
        ...
```

pytest class 风格让 `pytest -k TestSignature` 可以单独跑某一层。

## 不变量（v1 测试层最严苛的约束）

- **所有 V1 内置 adapter 必须通过对应合规测试**：V1 成功判据 6 的硬性条件。
- **测试不依赖具体 adapter 的内部实现**：合规测试是黑盒测试，不读 adapter 的源代码、不调用私有方法。
- **测试在干净环境下可重复运行**：每个测试用例不应假设其他测试的副作用。
- **新增 adapter 必须挂进 fixture**：不挂进 fixture 的 adapter 不算"通过合规测试"——这是结构性约束，写在 conftest.py 即可强制。
- **保留端口不写测试**：见上文"V1 范围"。这条约束本身要靠代码审查而非自动化保证（V1 没有 lint rule 强制"不写 test_channel_port_compliance.py"）。

违反这些约束的征兆：某个 adapter "看似能跑但不能装"（说明 manifest 撒谎，测试没抓到）；某个合规测试长时间不出错（说明它在测无意义的断言）；新加 adapter 后测试跑得不一样（说明测试有顺序依赖）。
