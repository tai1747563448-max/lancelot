# 06 · 插件开发指南

> 状态：草案 v1.0
> 读者：要写 Lancelot adapter 的开发者
> 范围：从零开始写一个 V1 adapter 的完整流程——V1 仅 memory 和 tools 两个类别

---

## 这是给谁的

如果你想：

- 给 Lancelot 加一种新的记忆后端（sqlite / redis / postgres / 文件 / 自定义）
- 给 Lancelot 加一种新工具（搜索 / 计算器 / 任何业务工具）

——这份文档就是给你的。

V1 范围内你可以写 **adapter**。V2 起可以写 **plugin**（运行时钩子）。本文档 V1 章节讲 adapter，V2 章节会在迁移时补。

## 这不是什么

- **不是 Lancelot 内部开发文档**：要改 Lancelot 自身（`src/lancelot/`）请看代码而不是看这份。
- **不是模型 provider 接入指南**：V1 不开放 model adapter（保留端口）。V1.1 起写 OpenAI / Anthropic adapter 见 [`01-V1范围与边界.md`](01-V1范围与边界.md) §"V2 已知的会破坏 V1 的引入"。
- **不是 multi-agent 编排指南**：multi_loop 是 Lancelot 内部扩展，不通过 adapter 接入。

---

## 完整工作流（V1）

六个步骤，从想法到能跑通：

```
[1] 选 port           → 决定实现 MemoryPort 还是 ToolPort
[2] 建目录            → adapters/<category>/<your-name>/
[3] 写 MANIFEST.toml  → 声明身份和入口
[4] 写实现            → __init__.py + adapter.py
[5] 跑合规测试        → 验证你的实现满足端口契约
[6] 端到端验证        → compose + launch 跑一次真实场景
```

下面一步步展开。

---

### 步骤 1：选 port

V1 只有两个候选：

| Port | 满足这个 port 的好处 | V1 实例参考 |
|---|---|---|
| `MemoryPort` | Lancelot loop 会调你的实现来存 / 取 / 列记忆 | `adapters/memory/inmemory/` |
| `ToolPort` | Lancelot loop 会把你的实现作为可调用工具暴露给模型 | `adapters/tools/echo/` |

**选错怎么办**：如果你的东西既是记忆又是工具，选 `ToolPort`——工具的实现门槛低（不需要并发安全、不需要容量管理），而记忆的实现约束多（必须有 clear 语义等）。

---

### 步骤 2：建目录

物理布局**强绑定**你的 adapter ID。

假设你要写一个基于 sqlite 的记忆 adapter，ID 打算叫 `memory.sqlite`：

```bash
mkdir -p adapters/memory/sqlite
cd adapters/memory/sqlite
touch MANIFEST.toml __init__.py adapter.py
```

布局：

```
adapters/memory/sqlite/
├── MANIFEST.toml      # 必填：自描述
├── __init__.py        # 必填：入口模块
└── adapter.py         # 推荐：实现逻辑（拆开 __init__.py 是为了 import 干净）
```

> **不要把实现直接写在 `__init__.py`**。`__init__.py` 应该尽量薄，只做 import 转手。把实际逻辑放到 `adapter.py`（或别的模块）里。

### ID 命名规则

格式：`<category>.<name>`

- `category` 必须是 `memory` 或 `tools`（V1 仅这两类）
- `name` 必须是小写字母、数字、下划线
- 整体正则：`^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$`

V1 内置 ID 范例：

- `memory.inmemory` ←→ `adapters/memory/inmemory/`
- `tools.echo` ←→ `adapters/tools/echo/`

---

### 步骤 3：写 MANIFEST.toml

完整 schema 见 [`02-Manifest协议.md`](02-Manifest协议.md)。这里给一个完整可用的 `memory.sqlite` 模板：

```toml
# adapters/memory/sqlite/MANIFEST.toml

[adapter]
id            = "memory.sqlite"
name          = "SQLite Memory"
version       = "0.1.0"
category      = "memory"
description   = "基于 sqlite 的持久化记忆（V1 不要求，但 layout 准备就绪）。"
min_framework = "1.0.0"

[entry]
module  = "memory.sqlite"     # 从 adapters/ 根算的虚线路径
factory = "create_memory"     # 该模块里的可调用名

[capabilities]
provides = ["MemoryPort"]     # 必须是 MemoryPort 或 ToolPort
requires = []                 # 可空；V1 无 adapter 互相依赖
conflicts = []
enhances = []

[config]
schema = {
    db_path     = { type = "str", default = ":memory:", required = false },
    max_entries = { type = "int", default = 10000,      required = false },
}
```

**易错点**：

1. **`[entry].module` 与 ID 不一致**：`module` 是从 `adapters/` 根算的 Python 虚线路径。`memory.sqlite` 这个 ID 对应的 module 是 `memory.sqlite`（注意：因为你的目录就是 `adapters/memory/sqlite/`，被加到 sys.path 后顶层就是 `memory`，子模块是 `sqlite`）。
2. **`[entry].factory` 拼错**：必须是该模块里的**变量名**，拼错会触发 ImportError。
3. **`category` 与目录前缀不一致**：`category = "memory"` 必须配 `adapters/memory/<name>/`。

---

### 步骤 4：写实现

#### 4.1 选 Python 类型风格

Lancelot 用 [`typing.Protocol`](https://docs.python.org/3/library/typing.html#typing.Protocol)——你**不需要**继承任何基类。**只要方法签名匹配**，你的类就被视为满足 port。

但有两个推荐：

- **不继承**：`class SQLiteMemory:` （不是 `class SQLiteMemory(MemoryPort):`）——这是 Lancelot 的纪律。
- **可选地标注**：`class SQLiteMemory: ... # type: ignore[memory-port]` 之类的注释仅给类型检查器看，运行时无影响。

#### 4.2 MemoryPort 实现模板

```python
# adapters/memory/sqlite/adapter.py

"""memory.sqlite —— 基于 sqlite 的 MemoryPort 实现。"""

from lancelot.domain import MemoryEntry


class _SQLiteMemoryImpl:
    """私有实现。下划线前缀是惯例（不是强制）。"""

    def __init__(self):
        # V1 简化：用一个内存 dict 演示。真正的 sqlite 实现接数据库连接。
        self._store: dict[str, MemoryEntry] = {}

    def put(self, entry: MemoryEntry) -> None:
        self._store[entry.key] = entry

    def get(self, key: str) -> MemoryEntry | None:
        return self._store.get(key)

    def list(self, limit: int = 100) -> list[MemoryEntry]:
        return list(self._store.values())[:limit]

    def clear(self) -> None:
        self._store.clear()


def create_memory() -> _SQLiteMemoryImpl:
    """Factory。V1 装配器在 generate 阶段调用本函数，不传任何参数。"""
    return _SQLiteMemoryImpl()
```

#### 4.3 ToolPort 实现模板

```python
# adapters/tools/calculator/adapter.py

"""tools.calculator —— 四则运算工具。"""

from lancelot.domain import ToolResult


class _Calculator:
    name = "calculator"
    description = "执行四则运算。args 接受 expression (str)，例如 '1+2*3'。"
    parameters_schema = {
        "type": "object",
        "properties": {
            "expression": {"type": "string", "description": "算术表达式"},
        },
        "required": ["expression"],
    }

    def invoke(self, **kwargs: object) -> ToolResult:
        expression = kwargs.get("expression", "")
        try:
            value = eval(expression, {"__builtins__": {}}, {})  # V1 简化；真实实现应该用 ast
            return ToolResult(tool_call_id="", content=str(value))
        except Exception as e:
            # V1 推荐：抛 ToolError 而不是返回 is_error=True，让 loop 知道出错了
            from lancelot.errors import ToolError
            raise ToolError(f"calculator error: {e}") from e


def create_tool() -> _Calculator:
    return _Calculator()
```

#### 4.4 `__init__.py` 转手

```python
# adapters/memory/sqlite/__init__.py

"""memory.sqlite —— 满足 MemoryPort 的 sqlite 实现。"""

from .adapter import create_memory

__all__ = ["create_memory"]
```

#### 4.5 错误处理纪律

**必须抛 Lancelot 错误家族异常**，不要抛裸 `Exception`：

```python
from lancelot.errors import (
    LancelotError,
    MemoryError,
    ToolError,
)
```

如果你的实现依赖第三方库（如 sqlite3、redis），catch 它们的异常后**包成** Lancelot 错误再抛：

```python
try:
    self._conn.execute(...)
except sqlite3.DatabaseError as e:
    raise MemoryError(f"sqlite put failed: {e}") from e
```

这条规则保证：上层捕获 `LancelotError` 就能抓住所有 Lancelot 相关问题，不会被 `sqlite3.OperationalError` 之类的"陌生异常"穿透。

### 步骤 5：跑合规测试

把新 adapter 注册进 fixture：

```python
# tests/compliance/test_memory_port_compliance.py

@pytest.fixture(params=[
    pytest.param(("memory.inmemory", create_memory), id="memory.inmemory"),
    pytest.param(("memory.sqlite", create_memory_sqlite), id="memory.sqlite"),  # ← 新增
])
def memory_adapter(request):
    adapter_id, factory = request.param
    instance = factory()
    yield adapter_id, instance
```

然后跑：

```bash
pytest tests/compliance/test_memory_port_compliance.py -v
```

合规测试套件详见 [`05-合规性测试规范.md`](05-合规性测试规范.md)。如果你的实现**任何一条**失败，说明它与端口契约有冲突——可能是签名错、可能是行为不符合。修代码，不修测试（合规测试是契约的代码强制，不是你的目标）。

---

### 步骤 6：端到端验证

跑一次完整 compose → launch 流程：

```bash
# 在仓库根
lancelot scan
# 应该看到你的 adapter 出现在列表里

lancelot compose --use memory.sqlite --use tools.echo --name smoke-test
# 生成 generated/smoke-test/

lancelot launch smoke-test
# 启动生成物
```

进入生成物后，输入一句话，验证：

1. 模型收到消息（mock 模型会回 echo）
2. 记忆存了（重启 launch 后再次查询还在——如果你实现了持久化）
3. 工具能调（如果你的工具被声明为可用）

如果端到端跑通了，你的 adapter 就"接入了 Lancelot"。

## 配置注入

V1 的 config schema 在 manifest 里声明，生成物启动时**通过 `configure(config_dict)` 注入**：

```python
# 你的 adapter 实现（如果想支持 config）
def create_memory() -> _SQLiteMemoryImpl:
    return _SQLiteMemoryImpl()

class _SQLiteMemoryImpl:
    def configure(self, config: dict) -> None:
        """V1 装配器在 instantiate 后调用一次。"""
        self._db_path = config.get("db_path", ":memory:")
        # ... 用 self._db_path 初始化连接 ...
```

V1 简化：`configure` 不是端口必须的方法，是 Lancelot 装配器的**约定**——只要你的实现类有 `configure(config: dict)` 方法，装配器就会在 `factory()` 之后调用一次。如果实现没有 `configure`，则用 manifest 里的 `default` 值。

V2 计划：把 `configure` 提升为 `MemoryPort`/`ToolPort` 的可选方法。

## 进阶主题

### 多文件实现

如果你的实现很大（比如 sqlite adapter 需要 db schema 迁移、redis adapter 需要连接池），拆目录：

```
adapters/memory/sqlite/
├── MANIFEST.toml
├── __init__.py
├── adapter.py              # 主类
├── schema.py               # 表结构定义
├── connection.py           # 连接池
└── migrations/             # 迁移脚本
    ├── v1.sql
    └── v2.sql
```

只要 `[entry].module` 指向的 `__init__.py` 能正确 export factory 即可。

### 性能 / 并发

V1 不强制并发安全。如果你写了线程安全的实现（建议写），不写也没关系。V2 引入并发时再补测试。

### 第三方依赖

如果你的 adapter 依赖第三方 Python 包（如 `redis`、`psycopg2`），需要：

1. 在 manifest 里加 `[dependencies]`（V2 起；V1 不强制声明）
2. 在 V1 阶段确保这些依赖已经在 Lancelot 运行环境里（V1 假设环境已装好）
3. 在生成物环境里也要装——V1 假设生成物运行环境与 Lancelot 运行环境一致

V2 起会引入依赖锁定机制。

## 提交到 Lancelot 仓库（如果你是贡献者）

流程：

1. fork Lancelot 仓库
2. 在 `adapters/<category>/<name>/` 写你的实现
3. 在 `tests/compliance/` 注册 fixture
4. 跑 `pytest tests/compliance/` 确保全绿
5. 跑 `lancelot scan` 确认你的 adapter 出现
6. 跑 `lancelot compose` + `lancelot launch` 做端到端验证
7. 发 PR

PR 标题格式：`[adapter] <category>.<name>: <一句话描述>`

## V2 迁移指南（预告）

V2 起你也可以写 **plugin**（运行时钩子）。plugin 与 adapter 的差异：

| 维度 | adapter | plugin |
|---|---|---|
| 物理位置 | `adapters/` | `plugins/` |
| 替换方式 | 重跑 compose | 放进 plugins/，生成物自己加载 |
| V1 | ✅ | ❌ 不实现 |
| V2 | ✅ | ✅ |
| Manifest 顶层表头 | `[adapter]` | `[plugin]` |
| Schema | 同一份 | 同一份 |

V2 起这份文档会加"plugin 视角"章节。V1 作者升级到 plugin 时，**只需**搬目录 + 改顶层表头——manifest 字段不变。
