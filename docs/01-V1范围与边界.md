# V1 范围与边界

> 版本：v1.0
> 状态：基线（V1 启动前不再修改）
> 读者：所有 V1 参与者

---

## 一句话定位

V1 是 Lancelot 元框架的**最小可用版本**：让用户从一组预置插件中选几个，跑一次真实的 agent 对话，并且能验证"换一种记忆实现，工具代码不动"。

---

## 在架构文档中的位置

Lancelot 整体架构文档 [`../整体架构设计.md`](../整体架构设计.md) 末尾给出了一条 8 步演化路径。V1 覆盖前 4 步 + 第 5 步的部分：

| 步骤 | 内容 | V1 覆盖？ |
|---|---|---|
| 1 | 领域层最小集 + 端口层最小集 + 最简装配器 | 是 |
| 2 | 第一个插件 + 最简生成器 | 是 |
| 3 | 第一个真能跑一次的 agent 框架 | 是 |
| 4 | 合规性测试基础设施 | **是（分水岭）** |
| 5 | 更多模块与功能 | 部分（仅 1–2 个参考插件） |
| 6 | 真正的依赖求解 | 否 |
| 7 | 分发机制（远程拉取 / 签名 / 版本约束） | 否 |
| 8 | 多入口（GUI / HTTP / IDE） | 否 |

V1 之后的所有步骤必须在不破坏 V1 已有判据的前提下增量引入。

## V1 范围内（必做）

### 领域层

以下概念的最小字段集和不变量：

- `Task`（任务）
- `Session`（会话）
- `Message`（消息）
- `ToolCall`（工具调用）
- `Memory`（记忆条目的引用）
- `Capability`（能力描述）
- `Plugin`（插件）
- `Manifest`（清单字段）

具体字段定义见 [`03-端口契约.md`](03-端口契约.md)。

### 端口层

- `ModelPort` —— 模型调用契约
- `MemoryPort` —— 记忆读写契约
- `ToolPort` —— 工具契约
- `ChannelPort` —— 输入输出契约
- `Registry` —— 全局注册表协议（端口层特有）

每个端口的具体方法、参数、异常、不变量见 [`03-端口契约.md`](03-端口契约.md)。

### 应用层（装配器）

四个动作必须全部实现：

- **scan**：读取所有已知位置的插件源文件，解析 Manifest，填充 Registry。**不执行任何插件代码**。
- **select**：根据用户指定 + 必需检测 + 冲突检测，决定最终组合。V1 不做完整的依赖求解。
- **generate**：把选中插件源文件复制到 `generated/<name>/`，生成组合代码、配置、入口。
- **launch**：运行生成出来的框架。可以省略（用户手动启动也可）。

应用层不实现任何 agent 框架的业务规则（agent 循环、上下文压缩、工具调度、记忆检索）。

### V1 自带适配器（位于 `src/lancelot/adapters/`）

- **模型**：1 个 mock 实现（接口对齐 OpenAI/Anthropic 风格，但实际不调用任何外部 API）
- **记忆**：1 个内存实现（无持久化）
- **channel**：1 个 stdin/stdout CLI 实现
- **agent 编排**：1 个单 agent 循环（最简）

### 参考插件（位于 `plugins/`）

作为"用户怎么写插件"的样板：

- `memory/inmemory` —— 满足 `MemoryPort` 的最小记忆插件
- `tools/echo` —— 满足 `ToolPort` 的最小工具插件（echo 模型回复）

每个参考插件必须带 Manifest、通过对应端口的合规性测试。

### 合规性测试（位于 `tests/compliance/`）

每个端口一份测试套件：

- `test_model_port_compliance.py`
- `test_memory_port_compliance.py`
- `test_tool_port_compliance.py`
- `test_channel_port_compliance.py`

**所有 V1 自带实现与参考插件必须通过**。这是接口约束从"声明"变成"强制"的关键一步。

### 生成物（默认输出到 `generated/<name>/`）

物理上独立、可在没有 Lancelot 装配器的环境运行的 CLI 形态框架。生成物结构见 [`07-生成物结构.md`](07-生成物结构.md)。

## V1 范围外（明确不做）

| 项 | 原因 |
|---|---|
| 真正的依赖求解器 | V1 只做必需检测 + 冲突检测，不做传递闭包、不做版本约束 |
| 插件市场 / 远程拉取 | v1 假设插件源文件就在本地已知目录 |
| 签名验证 / 信任机制 | V1 不预设信任模型 |
| GUI / HTTP API / IDE 插件 | CLI 之外的入口 |
| 多 agent 编排 | 仅有单 agent 循环 |
| 长期记忆持久化 | inmemory 实现不写盘 |
| REM 整合 / 主动遗忘 | 属于 V1 之后的记忆层增强 |
| 真实模型调用 | V1 用 mock，预留接口让 v1.1 接 OpenAI/Anthropic |
| 可视化插件选择 | CLI 参数或配置文件 |
| 插件热更新 | 生成期固定，运行期不变 |
| 国际化 / 本地化 | 中文文档优先 |
| 跨平台打包脚本 | Windows 优先，路径处理不预设 |

每一条"不做"都对应一条潜在的"看起来很合理"的需求侵蚀路径。如果未来想引入其中某条，必须先修订本文档。

## V1 成功判据（验收线）

V1 视为"完成"的硬性条件。**所有 7 条必须通过**：

1. **`lancelot scan`** 能列出 V1 内置的所有插件（含 mock 模型、inmemory 记忆、echo 工具、CLI channel）。
2. **`lancelot compose --use memory.inmemory --use tools.echo --use model.mock --use channel.cli`** 在 `generated/<name>/` 生成一个可独立运行的 Python CLI。
3. 启动生成的 CLI 后输入一句话，能跑完一次 agent 循环并得到回复（mock 模型回 echo）。
4. 把内置记忆实现替换为另一个 mock 实现（同样满足 `MemoryPort`），生成的框架不动一行组合代码就能跑。
5. **`pytest tests/compliance`** 全部通过，证明接口约束被强制。
6. 删除 `generated/` 后再跑一次 `compose`，能完整重生成（无隐式状态丢失）。
7. 把 `generated/<name>/` 整体复制到一台没装 Lancelot 的机器上，能直接 `python -m app.main` 跑起来（证明装配器独立性）。

第 4 条是接口契约的活体验证，第 5 条是接口契约的自动化验证，第 7 条是装配器独立性不变量的活体验证。这三条对应架构文档中的三个最关键不变量。

## 技术栈

按已对齐的方案：

- **实现语言**：Python（>= 3.11）
- **Manifest 语法**：TOML（用 `tomllib` 解析，`tomli_w` 写回）
- **生成物形态**：CLI（stdin/stdout）
- **文档节奏**：文档先行（7 份技术文档定稿后再写代码）

## 与后续版本的关系

V1 是基线，不是终点。V1.1 / V1.2 等后续小版本的引入原则：

- **不破坏** V1 任何一条成功判据
- **不修改** V1 文档中已定的契约（接口、Marshal、生成物结构），只能新增
- **新增** 必须单独修订 `01-V1范围与边界.md`（追加"V1.x 增量"小节，不修改本文）
- **破坏性变更** 必须开 V2，重置文档

## 与多 agent 设计文档的关系

[`../multiagent-architecture-design.md`](../multiagent-architecture-design.md) 是元框架未来造出的"某种 agent 框架"的一种设计提案（自演化 multi-agent 模式）。它**不属于** V1 元框架本身：

- V1 元框架只关心"如何组装"，不关心"组装出的 agent 框架长什么样"
- multiagent 那份设计可以作为 V1 之后的"参考生成物模板"或"案例研究"
- V1 期间不动那份文档
