# 03 · 端口契约

> 状态：草案 v1.0
> 读者：装配器维护者、adapter 作者、plugin 作者、合规性测试作者
> 范围：定义 Lancelot 的领域类型、5 个端口的方法签名、Registry 协议、错误体系

---

## 这是什么

端口（port）是一组**方法签名**的契约。它不包含任何业务规则，也不指定由谁实现——只规定"调用方可以期待什么"和"实现方必须提供什么"。

V1 定义 **5 个端口**：

| 端口 | 回答的问题 |
|---|---|
| `ModelPort` | 模型怎么调 |
| `MemoryPort` | 记忆怎么读写 |
| `ToolPort` | 工具怎么被调用 |
| `ChannelPort` | 输入输出怎么走 |
| `AgentLoopPort` | agent 循环怎么跑 |

**所有端口都是 abstract 的**：Lancelot 不内置任何具体实现。具体实现由 adapter（`adapters/`）或 plugin（`plugins/`，V2 起）提供。任何模块（adapter 或 plugin）都通过 manifest 声明它实现哪些端口（参见 [`02-Manifest协议.md`](02-Manifest协议.md) §`[capabilities].provides`）。

## 这不是什么

- **不是抽象基类**：Lancelot 不强制 adapter/plugin 继承任何基类。只要方法签名匹配，端口契约就视为被满足。
- **不是业务规则**：端口只规定方法"长什么样"，不规定"调完之后发生什么"。
- **不是数据格式**：领域类型（Message、Session 等）描述"是什么"，端口描述"能做什么"。两者层次不同，本文档一并给出是因为每个端口都引用领域类型。

## Python 类型风格：结构化子类型（Protocol）

Lancelot 用 [`typing.Protocol`](https://docs.python.org/3/library/typing.html#typing.Protocol)（PEP 544）定义端口。这给的是**结构化子类型**——adapter/plugin 不需要 `class Foo(ModelPort)` 显式继承，只要方法签名匹配即可。

```python
from typing import Protocol

class ModelPort(Protocol):
    def generate(self, messages: list["Message"]) -> "Message": ...

# MockModel 不继承 ModelPort，但满足 ModelPort
class MockModel:
    def generate(self, messages: list["Message"]) -> "Message":
        return Message(role="assistant", content="[mock] " + messages[-1]["content"])
```

这种风格的好处：跨团队、跨代码库解耦——adapter 作者不需要知道 Lancelot 提供了哪些 Protocol 类，只要满足方法签名就行。

V1 约束只到**方法签名匹配**，不要求：
- 显式继承（`class Foo(ModelPort)`）
- 类型检查器静态通过（V1 不引入 mypy/pyright 强制）
- 运行时类型标记

**符合性由 [`05-合规性测试规范.md`](05-合规性测试规范.md) 的测试套件来保证**——通过对比实际方法签名与 Protocol 描述、跑一组行为测试来确认实现真的满足契约。

## 领域类型

端口方法签名引用的所有类型。Lancelot 不引用任何外部 SDK 对象——模型供应商的 message 格式（OpenAI 的、Anthropic 的）由 `ModelPort` 实现内部转换，**不得穿透到领域层**。

### `Message`

对话中的一条消息。

```python
from dataclasses import dataclass
from typing import Literal

@dataclass(frozen=True)
class Message:
    role: Literal["user", "assistant", "system", "tool"]
    content: str
    tool_call_id: str | None = None      # 仅当 role==="tool" 时有意义
    tool_calls: list["ToolCall"] | None = None  # 仅当 role==="assistant" 时有意义
```

字段：
- `role` —— 消息角色。`user` / `assistant` / `system` / `tool`
- `content` —— 文本内容。V1 不支持多模态（图像、音频）
- `tool_call_id` —— 当 `role == "tool"` 时，对应调它那个的 `ToolCall.id`
- `tool_calls` —— 当 `role == "assistant"` 时，模型请求调用的工具列表

不变量：
- `role == "tool"` 时 `tool_call_id` 必须非 None
- `role == "assistant"` 时 `tool_calls` 可为 None 或非空列表

### `Session`

```python
@dataclass
class Session:
    session_id: str
    task_id: str | None             # 关联到 Task（可选）
    messages: list[Message]         # 对话历史
    metadata: dict[str, str]        # 任意键值对（用户/系统标注）
```

字段：
- `session_id` —— 全局唯一 ID
- `task_id` —— 可选，关联到顶层 `Task`
- `messages` —— 有序消息列表（最后一条是最新）
- `metadata` —— 任意键值对（V1 不限制 schema）

V1 简化：session 无状态机——不是 STARTED / RUNNING / COMPLETED 等状态机的迁移。V2 引入。

### `MemoryEntry`

```python
@dataclass(frozen=True)
class MemoryEntry:
    key: str
    value: str
    role: Literal["user", "assistant", "system", "tool"] | None = None
    timestamp: float | None = None  # Unix 时间戳
```

字段：
- `key` —— 唯一标识
- `value` —— 文本内容
- `role` —— 可选，对应消息角色（V1 不强制）
- `timestamp` —— 可选，Unix 时间戳（V1 不强制）

不变量：
- `key` 在同一个 `MemoryPort` 实例内唯一（V1 不要求跨实例持久）

### `ToolCall` 与 `ToolResult`

```python
@dataclass(frozen=True)
class ToolCall:
    id: str                          # 唯一 ID，与 ToolResult.tool_call_id 对应
    name: str                        # 模块名，例如 "tools.echo"
    arguments: dict[str, object]     # JSON-like 参数

@dataclass(frozen=True)
class ToolResult:
    tool_call_id: str                # 对应 ToolCall.id
    content: str                     # 工具返回的文本结果
    is_error: bool = False           # 工具是否报错
```

`ToolCall.Arguments` 用 dict 而非 typed dict 是有意识简化（不同 provider 不统一）。V1 不验证参数类型——`tools.echo` 接受任意参数。

### `Task`

```python
@dataclass(frozen=True)
class Task:
    task_id: str
    description: str                 # 人类可读的任务描述
    metadata: dict[str, str] = field(default_factory=dict)
```

V1 中 `Task` 主要用作会话元数据，不参与调度。V2 引入任务队列与状态机时扩展。

### `Capability`

```python
@dataclass(frozen=True)
class Capability:
    name: str                        # 例如 "MemoryPort"
    version: str                     # SemVer，例如 "1.0.0"
```

端口（port）的语义版本号。V1 简化：所有端口都是 `1.0.0`，版本号只是预留字段。

### `Adapter` 与 `Plugin`（自描述）

```python
@dataclass(frozen=True)
class Adapter:
    id: str                          # 例如 "memory.inmemory"
    name: str                        # 人类可读
    version: str                     # SemVer
    category: str                    # 枚举
    description: str
    min_framework: str
    entry_module: str                # 例如 "memory.inmemory"
    entry_factory: str               # 例如 "create_memory"
    provides: list[Capability]
    requires: list[Capability]
    conflicts: list[str]             # 其它 Adapter/Plugin 的 id
    enhances: list[str]
    config_schema: dict              # 见 §03

@dataclass(frozen=True)
class Plugin:
    """结构与 Adapter 相同；V1 仅作类型占位。"""
    id: str
    # ... 与 Adapter 相同的字段 ...
```

V1 不强制 `Adapter` 与 `Plugin` 共享字段——它们在 V2 才会合并。当前把它们写成相同结构是为了 V2 迁移时无需改 schema。

## 端口契约（v1）

### `ModelPort`

```python
from typing import Protocol

class ModelPort(Protocol):
    """模型调用契约。负责给定消息列表，返回模型回复。"""

    def generate(self, messages: list[Message]) -> Message:
        """同步生成。messages 是完整对话历史（不含模型即将生成的回复）。
           V1 不支持流式（streaming）——返回完整 Message。
           失败时抛 ModelError（见错误体系）。"""
        ...
```

V1 简化：
- 没有 `astream` / `astream` / 多模态 / tool_choice / temperature 等可调参数
- 模型供应商由实现内部处理，对外只暴露 `generate`
- 实现可以**接受额外 kwargs**（如 `mymodel.generate(messages, max_tokens=5)`），V1 不强制签名严格——`Protocol` 是结构化的，实现可以扩展

`generate` 单入口方法的好处：未来想加 streaming / async，只需要在 Protocol 里加新方法，已有的实现不会破坏（Protocol 是可选方法）。

### `MemoryPort`

```python
class MemoryPort(Protocol):
    """记忆读写契约。"""

    def put(self, entry: MemoryEntry) -> None:
        """存一条记忆。key 重复时覆盖。"""

    def get(self, key: str) -> MemoryEntry | None:
        """读一条记忆。key 不存在返回 None。"""

    def list(self, limit: int = 100) -> list[MemoryEntry]:
        """列出最近 limit 条记忆。V1 不保证顺序。"""

    def clear(self) -> None:
        """清空所有记忆。V1 不区分按用户清理 / 按类别清理。"""
```

V1 简化：
- 没有语义检索 / embedding search / 过期策略 / 持久化——V2 起
- 没有按 role 过滤 / 按时间过滤——V2 起
- 失败抛 `MemoryError`

### `ToolPort`

```python
class ToolPort(Protocol):
    """工具契约。负责被 agent 调用、执行一个动作、返回结果。"""

    @property
    def name(self) -> str:
        """工具名（给 LLM 看），例如 'echo'。"""

    @property
    def description(self) -> str:
        """工具描述（给 LLM 看）。V1 不限制长度。"""

    @property
    def parameters_schema(self) -> dict:
        """工具参数的 JSON Schema。V1 仅做参考——不强制校验。"""

    def invoke(self, **kwargs: object) -> ToolResult:
        """执行工具。kwargs 由 LLM 生成（来自 ToolCall.arguments）。
           失败抛 ToolError（被 is_error=False 包裹后返回也允许）。"""
```

`parameters_schema` 用 dict 而非 `TypedDict` 是有意识简化——JSON Schema 本身就是 dict 表达。

`name` 是属性而非方法是有意识选择：调用方希望"这是一个 echo 工具"是个静态属性，而不是每次 invoke 都问一次。

### `ChannelPort`

```python
class ChannelPort(Protocol):
    """I/O 契约。负责从外界读、向外界写。"""

    def read(self) -> Message | None:
        """读一条用户消息。EOF 时返回 None。"""

    def write(self, message: Message) -> None:
        """写一条消息（通常是 assistant 回复）。"""
```

V1 简化：
- 没有同步原语（没有 `pull()`, `push()`）——V2 引入 HTTP/WebSocket 时再重命名
- 没有流式事件——单条 Message 完整读入/写出
- read() 返回 `Message | None`（None 表示 EOF/连接关闭），而非异常——按 V1 默认体验"连接断了就别再问"

### `AgentLoopPort`

```python
class AgentLoopPort(Protocol):
    """agent 循环契约。负责跑一次对话直到结束。"""

    def run(self, session: Session) -> Session:
        """跑一次 agent 循环。输入 session，输出更新后的 session。
           '更新'指可能追加了 assistant 消息、tool 消息、调过 model、调过 tools、调过 memory。
           失败抛 AgentLoopError。"""
```

V1 简化：
- 只有一个入口 `run`，不带 streaming、不带 sub-agent、不带 interrupt
- session 是 in-out（同一对象被改）；V1 不要求 immutable
- V1 不强制 `run` 的最大调用次数——具体实现（single_loop）有自己的 `max_turns` 配置

### 端口之间的关系

```
                  ┌────────────┐
                  │ ChannelPort│
                  └─────┬──────┘
                        │ user message
                        ▼
┌───────────┐    ┌──────────────┐    ┌───────────┐
│ ToolPort  │◄───┤ AgentLoopPort├────► ModelPort │
└─────┬─────┘    └──────┬───────┘    └───────────┘
      │ tool call      │
      │               │
      │               ▼
      │         ┌────────────┐
      └────────►│ MemoryPort │
                └────────────┘
```

`AgentLoopPort` 是协调者，调用其他三个端口。`ToolPort` 反向（被 Loop 调用的同时需要读 Memory 来存借）。

V1 不强制依赖方向（实现层不引入 DI 框架），但 manifest 中 `requires` 字段必须正确声明——例如 `agent.single_loop` 的 `requires` 必须含 `ModelPort`、`ChannelPort`、`ToolPort`（示例见 [`02-Manifest协议.md`](02-Manifest协议.md)）。

## Registry 协议

Registry 不是端口，是端口层的全局表，记录所有已知模块（adapter + plugin）的元数据。

```python
class Registry:
    def register(self, entry: Adapter | Plugin) -> None: ...
    def find_by_id(self, id: str) -> Adapter | Plugin | None: ...
    def find_by_capability(self, capability: str) -> list[Adapter | Plugin]: ...
    def all(self) -> list[Adapter | Plugin]: ...
    def size(self) -> int: ...
```

约束：
- `register` 时若 ID 已存在，抛 `RegistryError`（不静默覆盖）
- `find_*` 不存在的 ID/能力返回 None 或空列表，不抛异常
- V1 不实现删除——registry 在装配器启动时填充、退出时丢弃

## 错误体系

Lancelot 自身定义根类 `LancelotError`，所有 Lancelot 内部异常继承自它。adapter/plugin 实现**必须**抛 Lancelot 错误家族的异常，禁止抛裸 `Exception`。

```python
class LancelotError(Exception):
    """Lancelot 错误根。"""

class LancelotConfigError(LancelotError):
    """配置错误（manifest 字段错、参数错）。"""

class ManifestError(LancelotConfigError):
    """Manifest 解析/校验失败。"""

class ManifestMissingError(ManifestError): ...
class ManifestParseError(ManifestError): ...
class ManifestInvalidError(ManifestError): ...
class ManifestKindMismatchError(ManifestError): ...
class DuplicateIdError(ManifestError): ...

class LancelotPortAddressError(LancelotError):
    """端口契约违反。"""

class PortContractViolation(LancelotPortAddressError):
    """实现不满足端口（缺方法、签名错）。"""

class RegistryError(LancelotPortAddressError): ...

class LancelotAdaptersError(LancelotError):
    """adapters/ 操作错误（resolve 失败、conflict 触发等）。"""

class RequireNotMetError(LancelotAdaptersError): ...
class ConflictError(LancelotAdaptersError): ...

class GenerateError(LancelotError): ...

class LancelotRuntimeError(LancelotError):
    """生成物运行时报错（model/tool/memory/channel）。"""

class ModelError(LancelotRuntimeError): ...
class MemoryError(LancelotRuntimeError): ...
class ToolError(LancelotRuntimeError): ...
class ChannelError(LancelotRuntimeError): ...
class AgentLoopError(LancelotRuntimeError): ...
```

错误分类原则：

- 装配阶段（scan/select/generate）→ `LancelotConfigError` / `LancelotAdaptersError`
- 启动阶段（launch） → `GenerateError`（如生成物目录缺失）
- 运行阶段（生成物运行） → `LancelotRuntimeError`

每条错误必须**附带人类可读的诊断**（什么含义、操作建议、相关上下文）。**禁止**让原始 `Exception` 穿透到用户层。

## 并发与异步（V1 sync-only）

V1 所有端口方法都是**同步**。不要求 `async/await`。

未来 V2 引入 async 时，每个端口加 `async def agenerate` 等同义方法即可（向后兼容，已有实现不需要改）。

V1 不提供 async 池、并发执行、协程调度。Agent loop 串行执行。

---

## 不变量（v1 端口层最严苛的约束）

- **端口契约不依赖具体实现**：Protocol 协议里**不引用**任何外部 SDK 类型（openai、anthropic、requests 等）。如果某个端口方法需要外部类型，外部类型必须先被包装成 Lancelot 领域类型。
- **领域类型不可变**：`Message` / `MemoryEntry` / `ToolCall` / `ToolResult` 都是 `@dataclass(frozen=True)`。V1 之后可重新评估。
- **错误家族统一**：所有 Lancelot 异常继承 `LancelotError`。其他异常（KeyError、ValueError）允许实现内部抛，但**禁止**穿透到用户层（生成物入口必须包成对应端口例外）。
- **Registry 不持久化**：registry 在 scan 时填充、退出时丢弃。重启必须重扫。
