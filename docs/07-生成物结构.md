# 07 · 生成物结构

> 状态：草案 v1.0
> 读者：用户（要看懂生成物的人）、Lancelot 维护者、生成物作者
> 范围：定义 `lancelot compose` 产出的 `generated/<name>/` 目录布局、每个文件的作用、独立性保证

---

## 这是什么

生成物（generated framework）是 Lancelot 装配器产出的、可以脱离 Lancelot 独立运行的框架代码。它由 `lancelot compose` 命令创建，是 V1 成功判据 7、8 的物质基础。

**bare Lancelot 不生成物**。`lancelot run` 直接调用 Lancelot 内部的 default 组合，不写任何文件——见 [`04-装配器协议.md`](04-装配器协议.md) §动作 5。本文档描述的是 `compose` 命令的产物。

## 这不是什么

- **不是 Lancelot 源码**：生成物是 Lancelot 的一个具体装配结果，不替代 `src/lancelot/`。
- **不是生产部署单元**：V1 生成物是开发期脚手架，不是生产级打包物（V2 才考虑 Docker / wheel）。
- **不是必须的可执行文件**：生成物是 Python 源码目录，不是二进制；运行它需要 Python 解释器。

---

## V1 范围

V1 生成物**只能**走 CLI 形态（stdin/stdout）。HTTP / WebSocket 等其他形态是 V2 范围。

V1 生成物**只能**包含：

- Lancelot runtime 的子集（loop + default model + default channel + domain + ports + errors）
- 用户选中的 adapter（V1 仅 memory 和 tools）
- 组合代码与入口

---

## 目录布局（with-adapter 模式）

`lancelot compose --use memory.inmemory --use tools.echo --name myapp` 生成的目录：

```
generated/myapp/
├── README.md                       # 给最终用户看的"这是什么 / 怎么跑"
├── config.yaml                     # 固化的选择（id、config 实例化值）
├── pyproject.toml                  # 生成物的依赖声明（V1 简化版）
├── app/
│   ├── __init__.py
│   └── main.py                     # 入口：python -m app.main
├── composition.py                  # 组合代码：实例化 adapter + 接入 loop
├── lancelot_runtime/               # 复制的 Lancelot runtime（不依赖 source tree）
│   ├── __init__.py
│   ├── domain/
│   │   ├── __init__.py
│   │   └── types.py                # Message / Session / MemoryEntry / ToolCall / ToolResult
│   ├── ports/
│   │   ├── __init__.py
│   │   ├── memory.py               # MemoryPort Protocol
│   │   ├── tool.py                 # ToolPort Protocol
│   │   ├── model.py                # ModelPort Protocol（保留）
│   │   └── channel.py              # ChannelPort Protocol（保留）
│   ├── loop/
│   │   ├── __init__.py
│   │   └── single_loop.py          # Lancelot 唯一 agent loop
│   ├── model_default/
│   │   ├── __init__.py
│   │   └── mock.py                 # V1 唯一 model 实现
│   ├── channel_default/
│   │   ├── __init__.py
│   │   └── stdio.py                # V1 唯一 channel 实现
│   └── errors.py                   # LancelotError 家族
└── adapters/                       # 复制的选中 adapter
    ├── memory/
    │   └── inmemory/
    │       ├── MANIFEST.toml
    │       └── __init__.py
    └── tools/
        └── echo/
            ├── MANIFEST.toml
            └── __init__.py
```

**完整复制原则**：`lancelot_runtime/` 是 `src/lancelot/` 的物理子集复制——生成物运行时**只 import 自己的 `lancelot_runtime/`**，不回头 import 装配器的源码。这保证独立性。

## 文件详细说明

### `README.md`（生成物自带）

```markdown
# generated/myapp

Lancelot 生成框架，由以下选项烘出：
- memory.inmemory
- tools.echo

## 怎么跑

确保 Python >= 3.11。在本目录：

    python -m app.main

## 它是什么

Lancelot 默认提供：单 agent 循环 + mock 模型 + stdio I/O。
你在生成时选了 1 个记忆模块和 1 个工具，烘进生成物。

## 怎么改

本生成物已被 Lancelot 烘好。如需修改选择，编辑 `config.yaml` 后重跑：

    lancelot compose --use memory.inmemory --use tools.echo --name myapp --force

或编辑本目录的 Python 代码直接修改（不推荐——下次 compose 会被覆盖）。

## 独立性

本目录可以拷贝到没有 Lancelot 的机器上直接跑。
仅需 Python >= 3.11。
```

### `config.yaml`

固化选择。生成物启动时**只读这个文件**——不回头问装配器。

```yaml
# generated/myapp/config.yaml

generation:
  timestamp: "2026-10-02T15:30:00Z"   # 生成时间（V1 仅作记录）
  lancelot_version: "1.0.0"
  selection:
    - adapter_id: "memory.inmemory"
      category: "memory"
      config:
        max_entries: 1024              # 从 manifest defaults 来的

    - adapter_id: "tools.echo"
      category: "tools"
      config: {}                       # echo 无 config

defaults:
  model: "lancelot_runtime.model_default.mock"
  channel: "lancelot_runtime.channel_default.stdio"
  loop: "lancelot_runtime.loop.single_loop"
  max_turns: 10                        # loop 默认参数
```

### `app/__init__.py`

空文件。仅让 `app/` 成为 Python 包。

### `app/main.py`（入口）

```python
"""生成物入口。

由 lancelot compose 生成。不建议手动编辑——下次 compose 会覆盖。

启动：
    python -m app.main
"""
import sys
from pathlib import Path

# 让 generated/<name>/ 成为 sys.path 的根
GENERATED_ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(GENERATED_ROOT))

import composition


def main() -> int:
    session = composition.start()
    try:
        composition.run(session)
    except KeyboardInterrupt:
        return 130  # 与 shell 约定一致
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### `composition.py`（组合代码）

```python
"""组合代码——把 adapter 接入 Lancelot loop。

由 lancelot compose 生成。手改可读，但下次 compose 会被覆盖。
"""
import yaml
from pathlib import Path

from lancelot_runtime.domain import Message, Session
from lancelot_runtime.loop.single_loop import create_loop
from lancelot_runtime.model_default.mock import create_model
from lancelot_runtime.channel_default.stdio import create_channel

# Adapter factory 的 import 来自生成的 adapters/ 子目录
from adapters.memory.inmemory import create_memory
from adapters.tools.echo import create_tool


CONFIG_PATH = Path(__file__).resolve().parent / "config.yaml"


def _load_config() -> dict:
    with CONFIG_PATH.open("r", encoding="utf-8") as f:
        return yaml.safe_load(f)


def start() -> Session:
    """实例化所有部件并组装 session。"""
    cfg = _load_config()
    selection = {item["adapter_id"]: item for item in cfg["generation"]["selection"]}

    # 实例化 model（保留端口，由 Lancelot runtime 提供）
    model = create_model()

    # 实例化 channel（保留端口，由 Lancelot runtime 提供）
    channel = create_channel()

    # 实例化 memory（adapter）
    memory_cfg = selection.get("memory.inmemory", {}).get("config", {})
    memory = create_memory()
    if hasattr(memory, "configure"):
        memory.configure(memory_cfg)

    # 实例化 tools（adapter 列表）
    tools = []
    if "tools.echo" in selection:
        tool = create_tool()
        if hasattr(tool, "configure"):
            tool.configure(selection["tools.echo"].get("config", {}))
        tools.append(tool)

    # 实例化 loop
    loop = create_loop(
        model=model,
        channel=channel,
        memory=memory,
        tools=tools,
        max_turns=cfg.get("defaults", {}).get("max_turns", 10),
    )

    # 准备初始 session
    return Session(
        session_id="local",
        task_id=None,
        messages=[],
        metadata={"generated": True},
    )


def run(session: Session) -> None:
    """运行生成物。loop 接管会话。"""
    # composition.py 这里只做"调度 + 错误收敛"
    # 实际逻辑在 loop 里
    raise NotImplementedError("loop 在 V1 单独实现；本文件是装配示例")
```

> V1 的 `composition.py` 与 `single_loop` 的实际接口会在实现阶段细化。本文档给的是**模板骨架**，用来给 Lancelot 维护者与生成物作者对齐预期。

### `lancelot_runtime/`（复制自 `src/lancelot/`）

V1 复制清单：

```
src/lancelot/
├── domain/                          → lancelot_runtime/domain/
├── ports/                           → lancelot_runtime/ports/
├── loop/single_loop.py              → lancelot_runtime/loop/single_loop.py
├── model_default/                   → lancelot_runtime/model_default/
├── channel_default/                 → lancelot_runtime/channel_default/
└── errors.py                        → lancelot_runtime/errors.py
```

**不复制**：

- `src/lancelot/cli.py` —— Lancelot 自己的命令行入口，生成物不需要
- `src/lancelot/application/` —— scan/select/generate/launch，生成物不需要
- `tests/` —— 合规测试是 Lancelot 的事，不是生成物的事
- `__main__.py` —— Lancelot 包入口

### `adapters/`（复制自选中的 adapter）

V1 复制逻辑：

- 选中的每个 adapter → 复制完整目录树（含 MANIFEST.toml + 全部 .py）
- 目录结构保留 `adapters/<category>/<name>/`（与 source tree 同构，便于调试）

**不复制**：

- `adapters/__pycache__/`
- 未被 `--use` 选中的 adapter

## 怎么运行

### 通过装配器（便利）

```bash
lancelot launch myapp
```

等价于 `cd generated/myapp && python -m app.main`，但装配器多一层错误检查（生成物目录存在、入口文件存在）。

### 直接跑（独立性验证）

```bash
cd generated/myapp
python -m app.main
```

不通过装配器、不依赖 Lancelot 源码——这是成功判据 8 的支撑命令。

---

## 独立性验证（成功判据 8）

把生成物拷到一台没有 Lancelot 的机器上：

```bash
# 源机器
cp -r generated/myapp /tmp/
cd /tmp/myapp
python -m app.main
# 期望：正常运行，与在源机器上一模一样
```

**不依赖项清单**（V1 生成物不应该依赖这些）：

- ❌ Lancelot 源码树（`src/lancelot/` 在源机器上的存在）
- ❌ 装配器二进制（`lancelot` 命令本身）
- ❌ `adapters/`（在源机器上的存在）
- ❌ 任何"指向 source tree 的相对路径"

V1 生成物**只依赖**：

- ✅ Python >= 3.11
- ✅ `pyproject.toml` 里声明的依赖（tomli_w / pyyaml / jinja2 等）
- ✅ 它**自己的** `lancelot_runtime/` 子目录里的代码

如果独立性验证失败，征兆是：

- 拷到新机器上 `ImportError`：说明有代码 `import src.lancelot` 而不是 `import lancelot_runtime`——回 composition.py / main.py 检查
- 拷到新机器上 `ModuleNotFoundError: lancelot_runtime`：说明 Lancelot runtime 没被复制——回 04 §动作 3 的复制步骤检查

## 边界情况

### 生成物目录已存在

`lancelot compose --name myapp` 在 `generated/myapp/` 已存在时报 `E_OUTPUT_DIR_EXISTS`，除非加 `--force`。

`--force` 行为：删除旧目录后重生成。

### 配置覆盖

用户可以编辑 `config.yaml` 后直接跑（不走装配器）。比如把 `max_turns` 从 10 改到 50，重启即生效。

但**不建议**改 `composition.py`——下次 compose 会被覆盖。

### 修改选中集合

重跑 `lancelot compose` 用 `--force` 重生成是正确路径。

不建议手动从 `generated/myapp/adapters/` 删 adapter——下次 compose 不知道你删了，会按 config 重生成回去。

---

## V1 简化清单

不做的：

- 生成 wheel / Docker 镜像
- 生成 `requirements.txt` / `pyproject.toml` 的完整锁定（V1 只生成骨架）
- 多入口（V1 只有 stdin/stdout）
- 热更新（生成物启动后不能改 adapter）
- 插件加载（V1 生成物按 adapter 编译，不支持 plugins/）

V2 计划：

- 生成物结构里加 `plugins/` 子目录（V2 plugin loader 启动时按需加载）
- 多入口（HTTP / WebSocket）

## 不变量（v1 生成物层最严苛的约束）

- **生成物不持有 Lancelot source tree 的引用**：所有 import 走 `lancelot_runtime.` 前缀而非 `src.lancelot.`。
- **生成物不持有装配器的引用**：生成物代码里不调用 `lancelot.scan` / `lancelot.compose`，不读装配器内部状态。
- **生成物不依赖外部 adapter 路径**：`adapters/` 是生成物内部的子目录，不是 source tree 的符号链接。
- **生成物可以被独立打包**：未来打成 wheel / Docker 时只需要 `generated/<name>/` 内的全部内容。
- **生成物可以被反复重新生成**：`--force` 重生成后行为一致（除了 timestamp）。

违反这些约束的征兆：

- 把生成物拷到其他机器跑不起来 → 违反独立性
- 在 `composition.py` 里看到 `from src.lancelot...` → 违反 source tree 解耦
- 在生成物里看到 `lancelot.compose` 调用 → 违反装配器解耦
