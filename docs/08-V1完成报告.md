## TL;DR — 30 秒读完

Lancelot V1 是一个**造 agent 框架的元框架**：它本身不会跟 LLM 对话，但它能让任何人
**从一组预置模块里挑几个、烘出一份可独立运行的 agent 应用**。

- 4 个子命令：`scan` / `run` / `compose` / `launch`
- 3 个内置 adapter：2 种记忆实现（inmemory / lru）+ 1 种工具（echo）
- 8 条端到端成功判据全部活体验证
- 30 个 compliance 测试全绿
- 单次 `lancelot compose` 生成的可执行框架**完全脱离 Lancelot 自己跑**

如果你想跳到代码：

```bash
git clone https://github.com/tai1747563448-max/lancelot
cd lancelot
pip install -e .
pytest tests/compliance/      # 30 passed in 0.07s
lancelot scan                # 列出 3 个内置 adapter
```

## 1. 它是什么——一分钟定位

### 一句话

> Lancelot 是一个**模板烘焙器**：读一组 adapter 的 manifest，按用户选择装配出一份可独立运行的 agent 框架代码。

### 类比

```
Python 解释器          →  跑 .py 文件
Lancelot 装配器        →  跑"造 agent 框架的脚手架"
agent 框架（生成物）   →  跑"造 agent 应用的脚手架"
agent 应用            →  真正跟 LLM 对话的程序
```

每一层都是"上一层产出的可独立运行的字节"。Lancelot 在第四层。

### 与其他项目的关系

Lancelot **不是** AgentFramework（项目目录 `E:\desktop\How_to_build_a_agent\AgentFramework`）
的子集或依赖。它们是**不同层**的东西——AgentFramework 是一个具体的 agent 框架实现，
Lancelot 是造 AgentFramework 这类东西的工具。AgentFramework 可以用 Lancelot 拼出来，
但 Lancelot 不 import AgentFramework 的任何符号，反之亦然。

## 2. 核心能力清单

### 2.1 4 个子命令（CLI 表面）

| 子命令 | 用途 | 是否生成文件 | 是否需要 adapter |
|---|---|---|---|
| `lancelot scan` | 列出本地可用的 adapter | 否 | 否（只读 MANIFEST.toml） |
| `lancelot run` | bare Lancelot 直接跑（不接 adapter） | 否 | 否 |
| `lancelot compose --use <id>... --name <name>` | 把选中的 adapter 烘进 `generated/<name>/` | 是（15 个文件） | 是 |
| `lancelot launch <generated-name>` | fork-exec 子进程跑已生成的 framework | 否（启动的是生成物） | 是 |

### 2.2 3 个内置 adapter

| ID | 类别 | 行为 | 用途 |
|---|---|---|---|
| `memory.inmemory` | memory | FIFO 淘汰，default 1024 entries | 进程内短期记忆（最常见的最小 demo） |
| `memory.lru` | memory | LRU 淘汰（get/put 都刷新顺序），default 512 entries | 验证"换 adapter 不动组合代码"——同 port 不同 impl |
| `tools.echo` | tools | 把 kwargs 序列化为 JSON 回显 | 最小 ToolPort 演示（不调外部 API） |

### 2.3 5 类退出码

| 退出码 | 触发条件 | 对应错误类 |
|---|---|---|
| 0 | OK | — |
| 1 | 其它未分类 Lancelot 异常 | `LancelotError` 兜底 |
| 2 | scan 阶段重复 ID | `DuplicateIdError` |
| 3 | select 阶段失败（ID 不存在 / 重复 / 冲突 / 端口需求未满足） | `AdapterNotFoundError`, `ConflictError`, `RequireNotMetError`, `DuplicateIdInSelectionError` |
| 4 | generate 阶段失败（输出目录已存在 / 复制失败 / 模板渲染失败） | `OutputDirExistsError`, `CopyFailedError`, `TemplateRenderFailedError` |
| 5 | launch 阶段失败（生成物目录或 main.py 不存在） | `GeneratedDirMissingError`, `MainPyMissingError` |

## 3. 架构概览

### 3.1 六层依赖（自底向上）

```
┌─────────────────────────────────────────────────────────┐
│ cli.py + __main__.py       ← 你在这里（用户入口）       │
├─────────────────────────────────────────────────────────┤
│ application/               ← 装配器业务                  │
│   state.py                                         │
│   registry.py                                       │
│   scanner.py                                        │
│   selector.py                                       │
│   generator.py                                      │
│   launcher.py                                       │
│   runner.py                                         │
├─────────────────────────────────────────────────────────┤
│ ports/ (4 个 Protocol)      ← 端口契约                  │
│   memory.py                                          │
│   tool.py                                            │
│   model.py      ← Lancelot 保留端口                  │
│   channel.py    ← Lancelot 保留端口                  │
├─────────────────────────────────────────────────────────┤
│ loop/                       ← Lancelot 内部的 agent 循环 │
│ model_default/              ← Lancelot 内部的 model 实现 │
│ channel_default/            ← Lancelot 内部的 channel 实现│
├─────────────────────────────────────────────────────────┤
│ domain/                     ← 8 个 dataclass（领域类型）│
│ errors.py                   ← 22 个异常类（统一家族）    │
└─────────────────────────────────────────────────────────┘
```

**关键纪律**：`adapters/` 是仓库根的**平行**目录，**不在六层里**——adapter 是被 application/ 扫描、烘进生成物的对象，不是 Lancelot 自身的依赖。adapter 可以 import `domain` 类型但**不该 import**——为保持 duck-typed 灵活性，adapter 推荐只用 `Any`。

### 3.2 数据流

```
adapters/<id>/<name>/MANIFEST.toml   ← 用户写
        ↓ scan
Registry（内存索引）                 ← 装配器内
        ↓ select
SelectionList（用户选中的 adapter）  ← 装配器内
        ↓ generate
generated/<name>/                  ← 产物
  ├── lancelot_runtime/             ← Lancelot 内部子集复制
  ├── adapters/<id>/<name>/         ← 选中的 adapter 复制
  ├── app/main.py                   ← Jinja2 渲染
  ├── composition.py                ← Jinja2 渲染（实例化 loop + 三件套 + adapter）
  ├── config.yaml                   ← Jinja2 渲染（固化选择）
  ├── README.md                     ← Jinja2 渲染
  └── pyproject.toml                ← Jinja2 渲染
        ↓ launch
子进程跑 python -m app.main         ← 真·对话
```

**核心不变量**：生成物**完全独立**——`generated/<name>/` 下没有 `lancelot/` 符号链接也没有 `PYTHONPATH` 依赖，复制到任何机器都能跑。

## 5. 怎么用——10 分钟跑通

### 5.1 安装

```bash
git clone https://github.com/tai1747563448-max/lancelot
cd lancelot
pip install -e .                  # 注册 lancelot 命令
```

### 5.2 最小路径

```bash
# 1. 看本地有什么 adapter
lancelot scan
# 输出：
#   id                           name                     ...
#   memory.inmemory              In-Memory Memory         ...
#   memory.lru                   LRU Memory               ...
#   tools.echo                   Echo Tool                ...

# 2. bare Lancelot 直接对话（不需要任何 adapter）
printf "hello\n" | lancelot run
# 输出：
#   > [mock] hello
#   >

# 3. 烘一份独立运行的应用
lancelot compose --use memory.inmemory --use tools.echo --name myapp
# 输出 15 个写入路径

# 4. 跑生成物（不依赖 Lancelot）
python generated/myapp/app/main.py <<< "hi"
# 输出：
#   > [mock] hi
#   >

# 5. 也可以走装配器再启动
lancelot launch myapp <<< "hi"
# 输出同上
```

### 5.3 换一个 adapter（演示 V1 的"组合抽象"）

```bash
# 把 inmemory 换成 lru——composition.py 不用动
rm -rf generated/myapp
lancelot compose --use memory.lru --use tools.echo --name myapp
python generated/myapp/app/main.py <<< "hi"
# 行为一样：[mock] hi
```

换 adapter 不动组合代码——这是 V1 抽象的**核心证据**。

## 6. 不做什么（V1 边界）

| 类别 | V1 不做 | 原因 |
|---|---|---|
| 模型 | 真实 provider（OpenAI/Anthropic/local） | V1 只 mock；model 是 Lancelot 保留端口（不在 `adapters/`） |
| 记忆持久化 | 跨进程保留 memory | V1 mock 是进程内；持久化是 V2 |
| 工具调用 | mock model 不会返回 `tool_calls` | 真实工具调用需要真 model；V1 留接口形状 |
| plugin loader | `plugins/` 目录留空 | V1 不实现——`state.plugins_root` 字段已预留 |
| 多 agent | 编排 / multi_loop | V2 才做 |
| 错误信息 i18n | 中英混合 | V1 不强求；V2 起明确单一语言 |
| 流式输出 | model.generate 是同步返回完整 Message | 真实流式需要协议层重设计 |

**记住一句话**：V1 是"骨架先行"的最小可用版本；任何让"V1 不算完整"的功能，**都已经规划**进 V1.1 / V2——只是没做。

## 7. 关键决策与不变量（给未来开发者）

未来给 Lancelot 写代码（不论是修 bug、加 feature、写 adapter），遵守这 7 条不变量：

1. **生成物不持有 Lancelot source tree 的引用**：所有 runtime import 必须用包内相对路径（`from .X` / `from ..X`），绝不写 `from lancelot.X import Y`。Generator 用 `shutil.copytree` 物理复制，不留符号链接。
2. **scan 不执行 adapter 代码**：scanner 只读 `MANIFEST.toml`，不 `import __init__.py`。adapter 实现里的代码在 generate 阶段才被 import。
3. **adapter 用 duck-typing**：adapter 不直接 import Lancelot 领域类型（`MemoryEntry` / `ToolResult` 等），用 `Any` + duck typing。这让 adapter 在 source tree 和 `generated/<name>/adapters/<id>/` 下都能跑。
4. **保留端口不可越**：`ModelPort` / `ChannelPort` 由 Lancelot 内部实现，adapter manifest `provides = ["ModelPort"]` 触发 `E_RESERVED_PORT` 警告（不阻止注册）。
5. **错误家族统一**：所有 Lancelot 异常继承 `LancelotError`；**所有错误类都在 `errors.py`**——不在 application/* 模块里再散落定义。
6. **退出码集中映射**：`cli._EXIT_CODE_TABLE` 是异常 → 退出码的单一映射点。launch 家族（5）必须先于 generate 家族（4）判断——这条不变量体现在表的元组顺序里。
7. **生成物不依赖 PYTHONPATH**：composition.py 渲染后只引用包内相对路径。生成物跑时不需要外部设置 PYTHONPATH。

## 8. 已知风险与未来演进

### 8.1 已知风险

| 风险 | 影响 | 现状 |
|---|---|---|
| cli 中文输出在 Windows cmd 下可能乱码 | 报告里 `[E_XXX]` 错误码行可读，描述行可能乱码 | 当前未处理；`PYTHONIOENCODING=utf-8` 可绕过 |
| 真 model 接入未做端到端验证 | 用户自己接 OpenAI / Anthropic 时可能踩到 `_invoke_tool` 边界 | 风险接受——V1 范围外 |
| adapter 数量增多后 scan 性能 | O(n) 扫描 adapter 目录；当前 n=3 无忧 | 风险接受——n > 100 时再优化 |
| 无并发 / 异步路径 | V1 所有 IO 都是同步 | 风险接受——multi_loop 是 V2 |

### 8.2 演进候选（未排期）

- **V1.1 真模型支持**：`model_default/openai.py` / `anthropic.py`；保留端口放开，adapter 可声明 ModelPort。
- **V1.2 plugin loader**：`state.plugins_root` 已有，差一个 loader + 选择算法。
- **错误信息 i18n**：当前中英混合，V2 起明确单一语言。
- **`examples/run_smoke.sh`**：一键跑完 8 条判据的演示脚本。
- **多 agent 编排**：multi_loop 是 Lancelot 内部扩展。
