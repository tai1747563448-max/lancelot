# 04 · 装配器协议

> 状态：草案 v1.0
> 读者：装配器维护者、用户（用 CLI 的人）、生成物作者
> 范围：定义装配器四个动作（scan / select / generate / launch）的输入输出、内部状态、错误处理

---

## 这是什么

装配器是 Lancelot 的**对外入口**——它是一个独立的可执行程序，承担 Lancelot 与用户打交道的主要职责。

V1 提供 4 个 CLI 子命令：

| 命令 | 何时用 |
|---|---|
| `lancelot scan` | 列出本地可用的 adapter |
| `lancelot run` | **bare Lancelot 直接跑**（v1.2 新增）—— 不接任何 adapter，直接对话 |
| `lancelot compose` | 把选中的 adapter 烘进生成物 |
| `lancelot launch` | 启动已生成的框架（也可以不通过装配器直接跑） |

装配器是元框架的"门面"，所有面向用户的行为都通过它。它跟运行时框架（生成物）之间通过**生成物目录**这个文件系统产物交换信息，不直接通信——这条边界保证生成物可以脱离装配器独立运行。

## 这不是什么

- **不是 agent 框架本身**：装配器不实现 agent 循环、不调模型、不存记忆。它只负责把这些能力"挑出来 + 接起来"。
- **不是运行时**：装配器执行完毕即退出，agent 跑在生成物进程里。
- **不是工具集**：装配器一次只做一件事（scan / run / compose / launch）；不试图提供"全功能 agent IDE"。

---

## 内部状态（v1）

四个动作共享同一份内部状态，在装配器进程内生命周期一致：

```python
@dataclass
class AssemblerState:
    adapters_root: Path            # 默认 ./adapters
    plugins_root: Path             # 默认 ./plugins（V1 留空）
    output_root: Path              # 默认 ./generated

    registry: Registry             # 由 scan 填充
    selection: list[Adapter]       # 由 select 填充
    name: str | None               # generate 的目标子目录名
```

V1 简化：状态仅在进程内存里，不持久化。重启必须重跑 scan。

## 动作 1：scan

### 输入

- `adapters/` 路径（默认 `./adapters`）

### 输出

- 控制台：每个 adapter 的简短描述（id / name / version / category / capabilities）
- 内部：填充 `AssemblerState.registry`

### 副作用

- **无文件写入**
- 仅读 `adapters/<id>/MANIFEST.toml`
- 不读 `adapters/<id>/__init__.py`（除了检查文件存在）
- 不调用任何 factory

### 错误处理

| 错误 | 行为 |
|---|---|
| `E_MANIFEST_MISSING` | 跳过该目录，warning，继续扫下一个 |
| `E_MANIFEST_PARSE` | 跳过该目录，warning，继续扫下一个 |
| `E_MANIFEST_INVALID` | 跳过该目录，warning，继续扫下一个 |
| `E_KIND_MISMATCH` | 跳过该目录，warning，继续扫下一个 |
| `E_RESERVED_PORT` | **warning**（不跳过），提示该 adapter 试图实现保留端口 |
| `E_DUPLICATE_ID` | 整个 scan 失败，退出码 2 |
| `E_CATEGORY_MISMATCH` | 跳过该目录，warning，继续扫下一个 |

### CLI 示例

```
$ lancelot scan
memory.inmemory    In-Memory Memory      0.1.0  memory   [MemoryPort]
tools.echo         Echo Tool             0.1.0  tools    [ToolPort]

Scanned 2 adapters, 2 OK, 0 errors.
```

### 不变量

- 多次调用结果一致（V1 不引入时间敏感的扫描——manifest 文件是只读的事实）
- scan 不修改文件系统任何内容
- scan 完成后 `state.registry.size() == OK 数量`

## 动作 2：select

### 输入

- `state.registry`（scan 后的结果）
- `--use <adapter-id>` 列表（CLI 参数）或 `--select-file <path>`（配置文件）
- 默认行为：`--use` 不指定时，V1 选 Registry 里所有 adapter（便于调试）；v1.2 修订：bare 模式由 `run` 处理，compose 必须显式 `--use`

### 输出

- `state.selection`：选中的 adapter 列表
- 控制台：每个 adapter 的简短确认

### 副作用

- **无文件写入**
- 仅对 Registry 做查询，不修改 Registry

### 错误处理

| 错误 | 行为 |
|---|---|
| `E_ADAPTER_NOT_FOUND` | 整个 select 失败，退出码 3 |
| `E_REQUIRE_NOT_MET` | 整个 select 失败，退出码 3 |
| `E_CONFLICT` | 整个 select 失败，退出码 3 |
| `E_DUPLICATE_ID_IN_SELECTION` | 整个 select 失败，退出码 3 |

### V1 算法

```
input: selection（CLI/配置文件指定的 adapter id 列表）
state: registry

def select(ids):
    result = []
    while ids not converged:
        for id in ids:
            if id not in registry: error E_ADAPTER_NOT_FOUND
            adapter = registry.find_by_id(id)
            if adapter.id in result: error E_DUPLICATE_ID_IN_SELECTION
            for conflict_id in adapter.conflicts:
                if conflict_id in [a.id for a in result]:
                    error E_CONFLICT(adapter.id, conflict_id)
            for req_port in adapter.requires:
                if no adapter in result provides req_port:
                    error E_REQUIRE_NOT_MET(adapter.id, req_port)
            result.append(adapter)
        # 一次扫描完成 → 检查新增的 require 是否又引发新约束
        # V1 实现：单跳收敛后停止；多跳留给 V2
    return result
```

V1 不做完整传递闭包求解——`while ids not converged` 实际上最多跑一次（V1 manifest 的 `requires` 只指端口，不指 adapter id，不存在"选了 X 必须选 Y"的链式约束）。链式约束是 V2 真依赖求解器的事。

### CLI 示例

```
$ lancelot compose --use memory.inmemory --use tools.echo --name myapp
Selected: memory.inmemory, tools.echo
```

## 动作 3：generate

### 输入

- `state.selection`
- `--name <generated-name>`（生成物子目录名，必填）
- `state.output_root/<name>`（生成物目标目录）

### 输出

- `generated/<name>/` 完整目录树
- 控制台：每个被复制/生成的文件路径

### 副作用

- **写文件**：复制 adapter 源文件 + 写入组合代码 + 写入配置 + 写入入口 + 复制 Lancelot runtime
- 不修改 source tree（`adapters/`、`src/lancelot/`、`plugins/` 全部只读）

### 错误处理

| 错误 | 行为 |
|---|---|
| `E_OUTPUT_DIR_EXISTS` | 整个 generate 失败，退出码 4（除非加 `--force`） |
| `E_COPY_FAILED` | 整个 generate 失败，退出码 4 |
| `E_TEMPLATE_RENDER_FAILED` | 整个 generate 失败，退出码 4 |

### 生成内容（V1）

```
generated/<name>/
├── README.md                       # 描述该生成物
├── config.yaml                     # 固化选择（id、config schema 实例化后的值）
├── app/
│   ├── __init__.py
│   └── main.py                     # 入口：python -m app.main
├── composition.py                  # 组合代码：实例化 + 连线
├── lancelot_runtime/               # 复制的 Lancelot runtime（loop、default model、default channel、domain、ports）
│   ├── __init__.py
│   ├── loop/single_loop.py
│   ├── model_default/mock.py
│   ├── channel_default/stdio.py
│   ├── domain/...
│   └── ports/...
└── adapters/                       # 复制的选中 adapter
    ├── memory/inmemory/
    │   ├── MANIFEST.toml
    │   └── __init__.py
    └── tools/echo/
        ├── MANIFEST.toml
        └── __init__.py
```

详细结构见 [`07-生成物结构.md`](07-生成物结构.md)。

### V1 算法

```
def generate(state):
    target = state.output_root / state.name
    if target.exists() and not force:
        error E_OUTPUT_DIR_EXISTS

    # 1. 复制 Lancelot runtime
    shutil.copytree(src/lancelot, target/lancelot_runtime)

    # 2. 复制选中 adapter
    for adapter in state.selection:
        src = adapters_root / adapter.path_part  # 例 adapters/memory/inmemory
        dst = target/adapters / adapter.path_part
        shutil.copytree(src, dst)

    # 3. 渲染并写入 composition.py
    render_template("composition.py.j2", target/composition.py,
                    adapters=state.selection,
                    default_model="src.lancelot.model_default.mock",
                    default_channel="src.lancelot.channel_default.stdio",
                    loop="src.lancelot.loop.single_loop")

    # 4. 渲染并写入 app/main.py
    render_template("main.py.j2", target/app/main.py)

    # 5. 渲染并写入 config.yaml
    render_template("config.yaml.j2", target/config.yaml, selection=state.selection)

    # 6. 渲染并写入 README.md
    render_template("README.md.j2", target/README.md, name=state.name)
```

模板用 Jinja2（V1 决定），不引入更重的代码生成框架。

### 关键纪律

- **生成的 composition.py 必须把 selection 写到 config.yaml**，让生成物运行时不需要重新做选择
- **复制而非引用** Lancelot runtime：生成物不应在运行时回头 import `src.lancelot/`——必须把所有 runtime 文件物理复制进去。这保证装配器独立性
- **adapter 也复制而非引用**：`adapters/<id>/__init__.py` 被复制到 `generated/<name>/adapters/<id>/__init__.py`，生成的组合代码 import 复制后的版本而非原始版本

## 动作 4：launch

### 输入

- `generated/<name>/app/main.py`（默认）或 `<generated-path>` 指定路径

### 输出

- 进程退出码

### 副作用

- **fork-exec** 一个 Python 子进程
- 子进程执行 `python -m app.main`
- 子进程 stdout/stderr 透传到装配器的 stdout/stderr

### 错误处理

| 错误 | 行为 |
|---|---|
| `E_GENERATED_DIR_MISSING` | launch 失败，退出码 5 |
| `E_MAIN_PY_MISSING` | launch 失败，退出码 5 |
| 子进程退出非零 | 透传子进程退出码 |

### CLI 示例

```
$ lancelot launch myapp
（等价于 cd generated/myapp && python -m app.main）
```

### 关键纪律

- launch **仅**是便利功能——用户完全可以不通过装配器启动生成物（`cd generated/myapp && python -m app.main`）
- launch 不修改装配器状态、不修改生成物
- launch 不做"自动 compose"——必须先生成物存在

## 动作 5（v1.2 新增）：run

### 这是什么

**bare Lancelot 直接跑**——不生成任何文件，直接调用 Lancelot 的内部 default 组合：

- `loop = single_loop.create()`
- `model = model_default.mock.create_model()`
- `channel = channel_default.stdio.create_channel()`
- `loop.run(session)` 启动对话

### 输入

- 无（不带任何 adapter）
- 可选：`--config <path>` 指定 Lancelot 内部默认实现的配置（如 mock 的 response_prefix）

### 输出

- 进程退出码

### 副作用

- **无文件生成**——`run` 不写任何文件
- 启动 stdin/stdout 会话
- 用户在 stdin 输入消息，Lancelot 用 mock 模型回 echo

### 错误处理

| 错误 | 行为 |
|---|---|
| 内部组件初始化失败 | 进程退出码非零 |
| 用户输入 EOF | 正常退出，退出码 0 |

### CLI 示例

```
$ lancelot run
[mock] hello world
> hi
[mock] hi
> (Ctrl+D)
```

### 关键纪律

- `run` 是 V1 成功判据 2 的支撑命令——证明 bare Lancelot 自洽
- `run` 与 `compose --use nothing` 的区别：`run` 不生成文件，`compose` 必须生成文件；V1 两者走不同代码路径
- `run` 不接受 `--use`，因为没有 adapter 可选

## CLI 完整命令清单（V1）

```
lancelot scan                          # 列出 adapter
lancelot run [--config <path>]         # bare 模式直接跑
lancelot compose --use <id>... --name <name> [--force] [--select-file <path>]
lancelot launch <generated-name>       # 启动已生成的框架
lancelot --version                     # 输出版本
lancelot --help                        # 输出帮助
```

V1 **不**提供：

- `lancelot install <adapter>`（V1 不实现远程拉取）
- `lancelot validate`（scan 已经做校验）
- `lancelot test`（compliance 测试走 pytest，不在 CLI 集成）

## 不变量（v1 装配器层最严苛的约束）

- **scan 不执行任何 adapter 代码**：仅读 `MANIFEST.toml`，绝不 `import` 或 `__init__.py`
- **装配器不持有生成物的运行时引用**：generate 完成后，装配器进程退出，生成物进程独立
- **生成物不持有装配器的引用**：生成物的代码可以脱离 Lancelot 源码树独立运行（成功判据 8）
- **select 与 generate 分离**：select 仅在装配器进程内有效，不写入生成物；generate 把 selection 固化进 `config.yaml` 后，生成物读 config 而非回头问装配器
- **run 不写文件**：bare Lancelot 跑一次不留任何磁盘痕迹

违反这些约束的征兆会立刻显现——比如"换台机器跑不动"（违反装配器独立性）、"scan 后多了个 `__pycache__`"（违反 scan 不执行）、"删了 generated 还能跑"（违反生成物独立性）。
